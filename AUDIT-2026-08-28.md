# Site audit, 2026-08-28

A full-site Playwright sweep against a production build (`next build` + `next start`),
plus targeted probing of every API route the failing pages touched.

**Result: 101 of 120 scanned pages failed the console-error scan before this work. After it, 87 of
91 pass, and not one of the 4 remaining failures is a page defect** — two are third-party notices,
one is a feed that published a non-image as an article image, and one is an AI provider that is out
of quota. Details at the bottom.

(The page count changes because the scan used to assert on 58 routes that no longer exist while
skipping 33 that do. See item 1.)

Run it yourself:

```bash
pnpm build && pnpm start                 # production build, port 3000
pnpm run test:errors                     # console-error scan, all pages
pnpm run test:run                        # 2254 unit tests
```

## What was wrong, and what changed

### 1. The console-error scanner was testing the wrong pages

`e2e/console-errors.spec.ts` carried a hand-maintained list of 116 routes. Commit `5eb46898`
("rebuild frontend") had deleted 58 of them, so the scan spent most of its run asserting on 404
pages, while **33 pages that do exist were never scanned at all** (`/explore`, `/intelligence`,
`/podcast`, `/trading`, `/dashboard/*`, `/x402`, `/widgets`, and more).

The list is now derived from `src/app/[locale]/**/page.tsx` at collection time, so a new page is
covered the moment it lands and a deleted one stops being asserted on. Next.js route prefetches
that the browser cancels on teardown (`net::ERR_ABORTED`, ~33 per page) are no longer counted as
errors, and Google's favicon service is treated as third-party.

`e2e/console-errors.spec.ts`

### 2. Every 404 the site served was broken

The root `not-found.tsx` was statically prerendered and rendered a bare `<html>` with no CSP
nonce. The site ships a strict `script-src` with no `unsafe-inline`, so **all six of Next's inline
flight scripts were blocked on every 404**, hydration never started, and the browser reported an
uncaught `Connection closed.`

The page now reads the nonce the same way Next does (from the `content-security-policy` request
header, falling back to `x-nonce`), reuses the allow-listed `ThemeScript`, and has a designed
layout with links out instead of a bare unstyled fallback pointing at `/en` (which redirects).

`src/app/not-found.tsx`

### 3. The whole provider framework was inert at request time

`registry.fetch()` reported `No provider chain registered ... Available: none` in a production
build, even though `instrumentation.ts` registers **23 chains** on startup. Next.js bundles the
instrumentation hook and each route into separate module graphs, so the startup hook populated one
registry object and every route handler read a different, empty one. Every endpoint built on the
framework silently dropped to whatever single-provider legacy path it happened to have.

The singleton now lives on `globalThis`, and `fetch()` registers the chains on demand if it finds
the category missing. `/api/funding-rates` went from a hard failure to serving live data from OKX.

`src/lib/providers/registry.ts`

### 4. Etherscan V1 is retired, and 24 call sites still used it

Every `https://api.etherscan.io/api` request now answers
`{"status":"0","message":"NOTOK","result":"You are using a deprecated V1 endpoint..."}`. That took
out gas prices, ETH supply, whale transactions and on-chain stats across the site, plus the
Basescan, Arbiscan and Polygonscan entries in the data-source catalog.

All 24 sites now use the V2 multichain endpoint (`/v2/api?chainid=<id>`), which accepts the same
API key. `ETHERSCAN_BASE` in `src/lib/constants.ts` documents the migration.

`src/lib/constants.ts`, 18 files under `src/lib` and `src/app/api`

### 5. Owlracle's gas adapter produced nothing but zeroes

The adapter read `data.baseFee`, `speeds[].gasPrice` and `data.lastBlock`, none of which exist in
Owlracle's v4 schema (it reports `maxFeePerGas`, `maxPriorityFeePerGas` and a per-tier `baseFee`),
and it mapped `estimatedFee` — a fee, in ETH — into `estimatedSeconds`. Every field came back `0`.
It also mapped the confirmation-time estimate from a value that is not a time.

Fixed against the real schema, with confirmation time derived from each tier's `acceptance` share
and the chain's average block time. A zeroed estimate now throws instead of being cached, so the
chain falls over to Etherscan or Blocknative rather than serving a column of zeroes.

`src/lib/providers/adapters/gas/owlracle.adapter.ts`

### 6. Eleven paid endpoints returned 500 instead of 402

`withX402` built the SDK wrapper at module load. The `@x402/next` wrapper synchronously starts
`httpServer.initialize()` and parks the promise, so with the facilitator unreachable the rejection
had nothing attached and Node reported an unhandled rejection while the server was still booting.
On the first request the SDK's un-caught `await init()` then threw, and the route answered `500`
with an empty body — a caller has no way to learn what to pay from that, and x402 clients read a
5xx as a dead endpoint.

The wrapper is now built inside the request (so the rejection is always handled) and any
initialization failure falls back to a locally-built 402 carrying the real payment requirements,
matching what the middleware gate already does. All eleven endpoints now answer a valid
`x402Version: 2` challenge.

`src/lib/x402/auth.ts`

### 7. `/api/narratives` failed on every single call

The route posted 40 articles with full descriptions, absolute links and pretty-printed JSON:
~9,400 tokens against the free Groq tier's 8,000-tokens-per-minute cap, so every request got a
`413`. Worse, `aiComplete` treated `413` as fatal and aborted the whole provider chain instead of
failing over to the 1M-context provider configured right behind it.

Both fixed: `413`, `408`, `422` and `5xx` now mean "this provider cannot serve this request, try
the next one", and the prompt references articles by index and truncates titles and summaries, so
it fits inside the smallest context window in the chain. The endpoint returns real narratives.

`src/lib/ai-provider.ts`, `src/app/api/narratives/route.ts`

### 8. A single scraper could take the API down for everyone on its IP

The repeat-429 hard block is keyed on client IP and evaluated in `botDetection`, which runs *ahead*
of the trusted-origin exemption in `rateLimitHandler`. IPs are shared — corporate NAT, mobile
CGNAT, VPN exits, CDN edges — so one abusive client behind such an address earned every real reader
behind it a one-hour `403` on every API route, including the site's own first-party page fetches.

Verified-HMAC and same-origin browser traffic is now exempt from the hard block; it is metered by
the trusted tier instead.

`src/middleware/bot-detection.ts`

### 9. Both bridge endpoints served an empty list with a 200

`getBridges` in `src/lib/apis/defillama.ts` called `https://api.llama.fi/bridges`, a path that has
never existed (bridges live on `bridges.llama.fi`), so it 404'd on every build and every request.
And `bridges.llama.fi` has since moved behind DefiLlama's paid plan and answers `402`. Both
endpoints returned `200` with nothing in it, which nothing could detect.

The duplicate implementation is gone — `defillama.ts` delegates to `lib/apis/bridges` — and when
the volume feed is unavailable the roster is built from the free `api.llama.fi/protocols` endpoint,
which carries all 169 bridges with real TVL and 24h change. `volumeAvailable: false` tells callers
not to render the zeroed volume fields, and the DeFi page's table ranks and labels by TVL in that
case rather than printing a column of zeroes. It also has an empty state now.

`src/lib/apis/bridges.ts`, `src/lib/apis/defillama.ts`, `src/components/DefiCharts.tsx`,
`src/app/[locale]/defi/page.tsx`

### 10. The public embed widgets showed hardcoded fake prices

`/embed/ticker` and `/embed/market` called `/api/prices?limit=20`, but that route requires an
explicit `coins` list and answers `400` without one. Every load failed, and both widgets fell back
to a hardcoded sample array — BTC at $97,500, ETH at $3,400 — shown to every visitor of every site
embedding them.

They now call `/api/market/coins?type=top&limit=N`, which is the top-N list, and show an honest
"unavailable, refreshes every minute" message instead of invented prices.

`src/app/embed/ticker/page.tsx`, `src/app/embed/market/page.tsx`

### 11. `/api-reference` 404'd, and `/docs/api` redirected into it

next-intl rewrites every non-API path into `/<locale>/<path>`. `/api-reference` lives outside the
`[locale]` segment, so the rewrite landed on a path no page matches. The page shipped in the build
and was unreachable; `/docs/api` 301s there, so the documented API reference link was dead.

Non-locale routes are now excluded from the locale rewrite. The page also had no `<html>` or
`<body>` — the app's root layout deliberately renders bare `children` — so the served document
started with a `<script>` tag and hydration failed. It has its own document shell now.

`src/middleware/intl.ts`, `src/app/api-reference/layout.tsx`

### 12. Assorted

- **The embed theme script dereferenced `document.body` from `<head>`**, where it does not exist
  yet, throwing `Cannot read properties of null (reading 'setAttribute')`. It writes to
  `document.documentElement` now, with matching CSS. `src/app/embed/layout.tsx`
- **`/en/hub` fetched `/api/market/global`**, which has never existed; the endpoint is `/api/global`
  and returns exactly the shape the component already parses. The hub's market cap, volume and
  dominance tiles had been reading zero. `src/components/hub/LiveDashboard.tsx`
- **`/api/archive?stats=true` answered 404** when the archive was simply empty. It returns `200`
  with `success: false`, which is the contract the client already handles.
  `src/app/api/archive/route.ts`
- **`upgrade-insecure-requests` was emitted on plain-http origins**, so the browser rewrote the
  site's own same-origin requests to `https` and they failed with `ERR_SSL_PROTOCOL_ERROR`. That
  broke every authenticated dashboard route under `next start`. The directive is now conditional on
  the origin actually being https. `src/middleware/security.ts`, `src/middleware/intl.ts`
- **`Footer` used the server-only `getTranslations`** while three client pages (`/search`,
  `/watchlist`, `/bookmarks`) render it themselves, so it threw at runtime and no footer appeared on
  any of them. It uses `useTranslations`, which works in both environments.
  `src/components/Footer.tsx`
- **`/_next/image` rejected plain-http remote images**, leaving broken thumbnails on articles from
  feeds that publish `http://` image URLs. The optimizer fetches server-side and re-serves from our
  own https origin, so nothing plaintext reaches the browser. `next.config.js`
- **`/api/funding-rates` returned `502` when every provider was out**, and swallowed the reason. It
  logs which layer failed and answers `503` with `Retry-After`.
  `src/app/api/funding-rates/route.ts`
- **The widget builder previewed production, not the running deployment.** The copyable snippet
  still names the canonical host, as it should, but the live preview iframe now loads from
  `window.location.origin`, so it previews the widget being configured rather than the deployed one.
  `src/components/WidgetBuilder.tsx`
- **The console-error scanner counted cancelled router traffic as failures.** Next prefetches every
  `<Link>` in the viewport and starts RSC fetches on navigation, then cancels whatever is in flight
  at teardown. Those, and cancelled document loads from auth redirects, are no longer errors.
  `e2e/console-errors.spec.ts`
- **`gas-fees.test.ts`'s Blocknative fallback test asserted nothing** — the adapter reads its key at
  module scope and refuses to run without one, so the chain skipped straight past it. The key is
  stubbed before import and Owlracle is excluded, so the test now checks the fallback it is named
  for. `src/lib/providers/__tests__/gas-fees.test.ts`

### 13. A second Groq client had the same failover gap

`src/lib/groq.ts` is a standalone client used by the flash-briefing and digest routes, separate from
the `aiComplete` chain. It typed 401 but not 429, so a spent free-tier daily allowance (1000
requests) reached callers as a generic `Error` and both routes answered **500** — a server fault, for
an upstream that is simply out of quota. `GroqRateLimitError` now types 402/429 and both routes
answer `503` with `Retry-After`. `aiComplete` already keys its provider failover off that error
name, so the chain can move past Groq too.

`src/lib/groq.ts`, `src/app/api/ai/flash-briefing/route.ts`, `src/app/api/digest/route.ts`

### 14. `/api/compare` broke the page it feeds

Two bugs, one behind the other. The route answered `500` whenever CoinGecko throttled and the shared
cache had nothing to serve, despite a comment claiming it would serve the last good copy; that is an
upstream availability problem and now returns `503` with `Retry-After`. With that fixed the endpoint
started answering `200`, which exposed the second bug: `summary.avgChange24h` was serialised as a
`.toFixed()` **string** while the client types it as a number and calls `.toFixed(2)` on it, throwing
`avgChange24h.toFixed is not a function` and taking down the comparison summary. It is a number now,
matching every other field in that object and the documented type.

`src/app/api/compare/route.ts`

## Known remaining (4 failures, 3 causes)

- **`/en/hub` → `/api/narratives` 503.** Honest, and the failover chain doing its job: Groq's free
  tier is out of daily requests (1000/1000) and Gemini answers
  `403 Lightning dunning decision is deny for project: projects/93741856042`, which is a Google Cloud
  **billing hold** on the project, not an IAM or code problem. Both configured providers are
  genuinely unavailable. **Owner action:** clear the billing hold, or raise the Groq tier. Nothing to
  change in code.
- **`/en/regulation` → `/_next/image` 400.** A feed published
  `https://knockoutstocks.com/api/stocks/CRM/embed` as an article image; it is not an image, and the
  optimizer correctly rejects it. `ArticleImage` already catches the failure and renders its
  fallback, so the page is right. Left alone deliberately: a heuristic guessing which remote URLs
  "look like images" would suppress legitimate ones from CDNs that serve images off `/api/` paths.
- **`/en/trading`** logs `Cannot listen to the event from the provided iframe, contentWindow is not
  available` from the TradingView widget while its iframe is still attaching. Emitted by
  TradingView's own script; the chart renders.

## How this was verified

The numbers above come from the real working tree: `pnpm build` (exit 0), `next start`, then the
scan against it. 2330 unit tests pass and `tsc --noEmit` is clean.

Partway through, `sdk/x402-conformance/` and `src/app/api/x402/` — in-flight, uncommitted work by
another agent in this shared worktree — used `./x.js` import specifiers that Turbopack could not
resolve to the sibling `.ts` files, which failed `next build` for the whole repo. Rather than edit
another agent's live files, an interim verification ran in an isolated copy with those directories
removed. That agent has since fixed the specifiers, and every number reported here is from the real
tree with their work included.

## Environment notes

Binance (`fapi.binance.com`) answers `451` and Bybit `403` from this network, so those two rungs of
the funding-rate chain cannot be exercised here. The chain fails over to OKX and serves live data,
which is the behaviour the fix was after.
